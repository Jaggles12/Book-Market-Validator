### WHAT WE WANT INSTEAD

We are building a generic engine that works across all genres. The romance example is just one clear failure case.

We want to refactor the genre inference so that:

1. **CanonicalGenre + expectedGenre act as the primary signal for genre family.**
   - Example families: Romance, MysteryThriller, SciFiFantasy, Horror, LiteraryFiction, YoungAdult, Children/MiddleGrade, Nonfiction.

2. **Amazon category paths are used to SUPPORT or refine that family, not override it with generic “Literature & Fiction > Contemporary Fiction” labels.**

3. When a path contains both generic fiction labels AND a specific genre signal, the specific genre wins.

   Concretely:
   - If a path contains "Romance" anywhere, and canonicalGenre is in the Romance family, THEN:
     - shelf should be "Romance"
     - friendlyGenreLabel should be something like "Contemporary Romance" (coming from canonicalGenre or a Romance mapping)
     - NOT "Literary Fiction" / "Contemporary Fiction".

   - Similarly for other families in the future:
     - "Mystery", "Thriller" → MysteryThriller
     - "Science Fiction", "Fantasy" → SciFiFantasy
     - "Horror" → Horror
     - "Teen & Young Adult" → YoungAdult
     - "Children's Books" → Children/MiddleGrade
     - Only when there is NO specific family signal and paths are just "Literature & Fiction > Contemporary Fiction" should we fall back to "Literary Fiction".

4. The existing top-level UI “fiction vs nonfiction” selection should remain as a **gate**, not a dictator of subgenre:
   - If UI says `category: 'fiction'`, ignore nonfiction families like Self-Help, Business, Parenting.
   - If UI says `category: 'nonfiction'`, ignore obviously fiction families like Romance, Mystery, SFF, Horror.
   - Do NOT let a subtype like “general fiction” force the result into Literary Fiction if canonicalGenre + Amazon paths clearly say Romance, Mystery, etc.

5. Category purity should be computed **against the chosen genre family**, not a mismatched “general fiction” baseline:
   - For the example above, purity should be high (close to 1.0) for the Romance family.
   - We should NOT ever see `categoryPurity: "0.000"` when all core books have romance-centric paths.
